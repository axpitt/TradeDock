# Trade Dock --- UI Design System Brief

## 1. Visual source of truth

The application must use one coherent visual system across all pages.

Do not redesign the visual identity independently per page.

## 2. Required qualities

-   Modern
-   Premium
-   Focused
-   Trading-oriented
-   Data-rich but not cluttered
-   Professional
-   Fast
-   Scannable

Avoid generic SaaS styling and spreadsheet-like density.

Do not imitate TradingView directly.

## 3. Consistency rules

Reuse the same:

-   Color system
-   Typography hierarchy
-   Sidebar
-   Buttons
-   Inputs
-   Cards
-   Borders
-   Radius
-   Shadows
-   Icons
-   Status indicators
-   Spacing scale
-   Header treatment

New components must look native to Trade Dock.

## 4. Radar density

Radar is a monitoring board, not a marketing dashboard.

Prioritize:

-   More cards visible
-   Less vertical waste
-   Clear stock/score
-   Clear CMP/entry/distance
-   Immediate status recognition

## 5. Status language

Suggested states:

-   ACTIVE
-   ALERT ISSUE
-   APPROACH ALERT HIT
-   ENTRY REACHED
-   PINNED
-   CANCELLED / RESOLVED

Do not use unrelated trading terminology such as trailing stop unless
later approved.

## 6. Accessibility and interaction

Interactive elements should have:

-   Clear hover state
-   Focus state
-   Keyboard accessibility
-   Readable contrast
-   Clear feedback

Hover popovers must not be the only way to access critical information
on touch devices.

## 7. Empty states

Empty states should explain what the user can do next.

Examples:

Radar empty: "No trades are currently within the Radar zone."

All Trades empty: "No trades yet. Add your first trade."

Activity empty: "No recent activity."

## 8. Loading and error states

Use the same visual language as the main product.

Do not invent a separate loading design for each page.
